`/slack-ingest` — Slack 에서 오간 대화를 사용자와 **대화하며** ① 지식화(brain/wiki) ② **확인할 것·빠뜨린 것·태스크 후보** 추출을 한다. 위키에는 합성·마스킹한 결과만 올린다.

> **원문은 두 곳에서 온다**(2026-09-17, CLAUDE.md §7.7).
>
> | 채널 | 읽는 곳 | 필요한 것 |
> |---|---|---|
> | **공개 채널** (NAS 에 있는 것) | **NAS 공용 아카이브** `\\192.168.0.225\wiki-share` → `tools/slack-ingest/nas_slack.py`. 분석파트 워크스테이션이 매시 받아 개인정보를 가린 사본이고, 메시지마다 슬랙 원문 링크가 있다 | 사내망(재택은 VPN) + NAS 로그인. **토큰 필요 없음** |
> | **비공개 채널** (선택) | 개인 토큰 수집 `raw/slack/<채널>/` → `tools/slack-ingest/fetch_slack.py` | Slack 토큰 + `channels.json` |
>
> 연결이 안 되어 있으면 [SLACK-GUIDE.md](../../SLACK-GUIDE.md) 순서로 안내한다. 도구 설명은 `tools/slack-ingest/README.md`, 전사 안내는 전사 위키 `wiki/playbooks/slack-archive.md`. 위키 schema 는 `CLAUDE.md`(§4.3 raw, §7.7, §15 task-board, §17 전사 연계), 태스크는 [[tasks/board]].
> 분석파트가 배포하는 `/slack-compile` 과 역할이 같다. 이 커맨드가 있으면 따로 설치하지 않는다.
> 핵심: 다 올리지 않는다 — **신호 있는 것만**(§7.1·§11). 놓침 방지·우선순위·팀 방향이 1순위 가치.

## 0. 지키는 것 — 공용 아카이브 원칙

1. **NAS 에 있는 채널은 개인 토큰으로 따로 받거나 읽지 않는다.** NAS 의 마스킹이 외부 LLM 으로 나가는 유일한 관문이라, 같은 공개 채널의 가리기 전 원문을 따로 읽으면 그 관문이 무의미해진다. `fetch_slack.py` 는 채널 ID 로 판정해 건너뛴다.
2. **출처 없는 문장을 쓰지 않는다.** NAS 에서 온 항목은 메시지 링크 `[↗](https://bodit.slack.com/archives/<채널ID>/p…)` 를 단다. 비공개 채널 항목은 링크 없이 `src:#채널 YYYY-MM-DD` 만 남긴다. 첨부 파일 링크는 옮기지 않는다.
3. **숫자·결론을 그대로 확정하지 않는다.** NAS 본문은 사람이 검토하지 않은 기계 가공본이다. 날짜·발화자까지만 믿고, 숫자는 "슬랙에서 누가 이렇게 말했다" 로 적는다. 사실로 확정해 위키·이슈에 올릴 것은 링크로 원문을 확인한다.
4. **가려진 값은 복원하지 않는다.** `{TEL_…}`·`{NAME_…}`·`{ACCT_…}` 같은 토큰과 `{SECRET}` 은 값 자체가 없다.

## 1. 대상 확보

### 1-1. NAS (공개 채널)
- **연결 확인**: `python tools/slack-ingest/nas_slack.py --check`
  - 닿지 않으면(종료 코드 3) 사내망·VPN·NAS 로그인을 확인하라고 안내한다([SLACK-GUIDE.md](../../SLACK-GUIDE.md) 2절). 비공개 채널 수집이 설정돼 있으면 그쪽만 진행할지 묻는다.
  - "마지막 갱신" 이 2시간보다 오래됐으면 워크스테이션 수집이 멈춘 것이다. 분석파트에 알리자고 제안한다.
- **`$ARGUMENTS` 가 비었으면**:
  1. 분량 먼저: `python tools/slack-ingest/nas_slack.py --pending --stats`. **2만 토큰을 넘으면** 채널을 좁힐지(`--channels`) 먼저 묻는다. 처음 쓰는 사람은 커서가 없어 최근 7일이 잡히므로 대개 좁히는 편이 낫다.
  2. 본문: `python tools/slack-ingest/nas_slack.py --pending [--channels …]`. 커서 이후 메시지가 채널·날짜별로, 메시지마다 `[↗]` 링크와 함께 나온다.
- **기간·채널이 지정됐으면**(오늘 날짜 기준 구체 날짜로 환산):
  - `YYYY-MM-DD`·`어제`(하루) → `--since D --until D` / `A..B`·`A ~ B` → `--since A --until B` / `지난주` → 지난 월~일 / `최근 N일`·`N일`·`일주일` → `--last-days N`
  - 채널명이 섞여 있으면 `--channels 이름1,이름2`. NAS 에 없는 채널이면 1-2 로 넘긴다.
  - 날짜 파일 기준이라 며칠 뒤 달린 답글도 원글 날짜에 함께 나온다.

### 1-2. 비공개 채널 (선택 — `channels.json` 과 토큰이 있을 때만)
- 설정이 없으면 이 단계를 조용히 건너뛴다. 사용자가 비공개 채널을 원하면 [SLACK-GUIDE.md](../../SLACK-GUIDE.md) 3~6절을 안내한다.
- **채널은 사용자가 고른다**(전체 자동 수집 금지). `$ARGUMENTS` 에 채널명이 있으면 그 채널만, 없으면 `channels.json` 의 `include` 를 보여 주고 고르게 한다.
- 호출: `python tools/slack-ingest/fetch_slack.py [--channels …] <기간 인자>` (기간을 안 주면 `--since-cursor`, 채널별 지난번 수집 이후~지금).
  - NAS 에 있는 채널은 수집기가 건너뛰었다고 알려 준다. 그대로 두고 1-1 에서 읽는다.
  - `SLACK_TOKEN` 에러면 이 단계만 멈추고 `tools/slack-ingest/README.md` 1.1 을 안내한다.
  - 채널명이 안 풀리면 `--list-channels` 로 실제 채널명 확인을 제안한다.
  - 끝에 출력되는 **manifest(읽을 파일 목록)** 를 확보한다.
- NAS·비공개 둘 다 "새 메시지 없음" 이면 그 사실만 보고하고 종료한다.

## 2. 읽기 + 1차 정리 (요약 남발 금지)

- 1-1 출력과 1-2 manifest 의 `raw/slack/<channel>/*.md` 를 읽는다. **장황한 채널별 요약을 쏟지 않는다.**
- **기능 채널·태그로 목적지를 먼저 잡는다**(기능별 논의 방식 A+B, 이름 규칙은 전사 위키 `wiki/features/README.md`):
  - **A. 기능 채널** `<제품>-feat-<기능>` (예: `fh-feat-분만-알림`, 제품 접두어 `fh` Farmershands · `bs` Bodystamo · `bd` 공통) — 전사 위키에서 머리말 `slack:` 이 이 채널 이름인 기능 페이지가 목적지이고, GitHub 라벨은 `<제품>-feat:<기능>` 이다. 이 채널에서 나온 결정·변경은 **그 기능 페이지의 타임라인 후보**로 모은다. 사람에게 분류를 묻지 않는다. 페이지가 아직 없으면 만들자고 제안한다.
  - **B. 머리말 태그** `[<제품>-<기능>]` (예: `[fh-분만-알림]`) — 기존 채널에서 메시지 첫머리에 태그가 붙어 있으면 그 기능으로 묶는다. 태그가 없으면 평소처럼 내용으로 판단한다.
  - 기능 채널이 조용해진 지 오래됐는데 기능 페이지에 결론이 없으면 **"결론 정리 후 채널 보관"** 을 제안한다.
- 머릿속으로 다음 5가지를 채널 가로질러 추린다(아직 위키에 쓰지 않음):
  1. **지식화 후보** — 결정·기법·entity·개념·도메인 지식(6개월 후 참조 가치).
  2. **확인 필요** — 직접 봐야 할 것(멘션·질문·승인 요청·본인 결정 대기).
  3. **빠뜨린 것·놓친 것** — 답 안 한 멘션, 흘러간 요청, 방치된 blocker.
  4. **태스크 후보** — 액션 아이템(담당·기한 가늠).
  5. **팀 방향 신호** — 팀원이 막힌 것, 내가 방향 줄 것.
- **마스킹**(§9, `sensitive` 채널은 더 강하게): NAS 본문은 전화·이메일·외부인 실명·계정이 이미 토큰으로 가려져 있지만, 농장명·농장 ID·개체 ID 는 원래 값이다. 올리는 결과물에서는 개체번호·개인정보·급여·계약액·고객 식별을 걷어낸다. Slack 링크는 **공개 채널 메시지 링크만** 남긴다.
  - ⚠️ **비공개 채널 원문(`raw/slack/`)은 git 에 올라간다**(§4.3). 개인 위키가 포크면 조직 구성원이 볼 수 있으므로 첫 수집 전에 [SLACK-GUIDE.md](../../SLACK-GUIDE.md) §1-1 을 확인한다. 수집 직후 raw 에 토큰·계정·급여·개인 식별 정보가 남아 있으면 **커밋 전에 지적하고 확인**받는다. 인사·면담 채널은 애초에 `channels.json` 의 `exclude` 로 뺀다.

## 3. 사용자와 대화 (짧게, 칸 채우기식)

추린 결과를 **압축해서** 제시하고 분류를 받는다:
- **확인 필요·놓친 것 먼저** (놓침 방지가 최우선): "이것들 보셨나요? / 답 필요해 보입니다" — 각 1줄, NAS 항목은 `[↗]` 를 붙여 바로 열 수 있게 한다. 처리/무시/태스크화 선택.
- **태스크 후보**: 보드로 보낼 것 추려 제시 → 승격 여부·우선순위·담당·기한 확정.
- **지식화 후보**: 후보를 1줄씩 → brain note / decision / entity·concept 중 무엇으로, 또는 스킵. 애매하면 **brain seed 로 가볍게**.
- 답이 얇은 칸만 되묻는다.

## 4. 반영

확정된 것만 쓴다. 출처 표기는 **NAS 항목 `src:#채널 YYYY-MM-DD [↗](링크)`**, **비공개 항목 `src:#채널 YYYY-MM-DD`** 로 통일한다.
- **태스크 보드** [[tasks/board]]: 확인 필요→`## 👀 확인 필요`, 태스크→적절한 섹션. 라인 포맷 `- [ ] <할 일> · src:#채널 YYYY-MM-DD · @담당 · due:… · note:…`. `last_updated` 갱신.
  - **공유 할 일**(담당이 다른 사람, 남과 약속한 마감, 다른 파트·외부가 결과를 받음, 누군가 기다림, 코드 PR 로 끝남)은 보드에만 쓰지 않는다. `tools/company-wiki.py task-new` 를 `--yes` 없이 실행해 미리보기를 보여 주고, 승인받은 뒤에만 `--yes` 로 issue 를 만든다(CLAUDE.md §17.3). 본문 "출처" 절에 NAS 항목의 메시지 링크를 적는다. 보드에도 남기면 그 줄에 `gh:<owner/repo#n>` 을 붙인다.
- **brain note**: 생각·교훈·가설 → `brain/<slug>.md`. seed 로 가볍게 시작 OK. **고립 금지**.
- **wiki 승격**: 확정 결정 → `wiki/decisions/YYYY-MM-<slug>.md`(§7.6), 새 사실·개념 → `wiki/entities`·`wiki/concepts` 갱신/신규(§7.1). Sources 에는 비공개 원문이면 `[[raw/slack/<채널>/<날짜>]]`, NAS 항목이면 메시지 링크를 적는다(NAS 는 로컬 파일이 아니라 wikilink 가 안 된다).
- **전사 승격 판정**(§17): **회사 공용 결정·용어·프로젝트 지식**이면 마스킹·합성해 전사 승격을 제안한다(`/promote`). 비공개 채널發이라도 공용 지식을 개인 위키에 가둬두지 않는다 — 단, 발언자·비공개 맥락과 비공개 채널 링크는 걷어낸다.
- 단순 잡담·일회성은 **승격 안 함**.

## 5. 마무리
- `index.md` 신규 페이지 반영, `log.md` append: `## [YYYY-MM-DD] slack-ingest | <기간> NAS <N>ch + 개인 <M>ch` + 보드/brain/wiki 변경 줄.
- **채팅 한 줄 보고**: 확인 필요 N · 태스크 신규 M · 지식화 K · 전사 승격 후보 J · 미처리로 남긴 것.
- **NAS 커서 전진** — 다 반영했으면 `python tools/slack-ingest/nas_slack.py --mark`. 방금 `--pending` 으로 **본 데까지만** 옮긴다(채널을 좁혀 봤으면 그 채널만). 빼먹으면 다음에 같은 대화를 또 읽고, 중간에 끊었으면 **전진시키지 않는다**. 기간을 지정해 읽은 경우에는 커서를 건드리지 않는다.
- 변경 commit 제안(요청 시). `.env`·커서·`channels.json` 은 `.gitignore` 라 커밋 안 되고, **`raw/slack/*.md`(비공개 원문)는 커밋된다** — 마스킹 확인 후 stage. NAS 본문은 로컬에 복사하지 않으므로 커밋할 것이 없다.

## 톤·안전
- 사용자와의 대화는 **존댓말**. 위키 본문·brain·보드는 **평어체**.
- 원문(`raw/slack/`)은 immutable. 위키 페이지엔 **마스킹·합성**만.
- NAS 사본은 **외부로 내보내지 않는다**(전사 playbook). 위키에 통째로 옮기지 않는다.
- 민감 채널·개인정보·계약·고객 식별은 raw·보드·위키 어디서도 마스킹. 애매하면 멈추고 묻는다.
- 인사·채용 등 민감 채널은 `channels.json` exclude 로 수집 대상에서 뺀다.
- **비공개 채널을 임의로 확장하지 않는다** — 사용자가 고른 채널만 받는다.
