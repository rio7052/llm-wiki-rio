`/promote` — 개인 위키에 쌓인 것 중 **회사 공용 가치가 있는 것만** 전사 LLM wiki 로 올린다. CLAUDE.md §17 의 정형화. `/eod` 6단계가 하루 단위로 호출하는 절차를 단독으로도 쓸 수 있게 한 것.

> 핵심: **복사가 아니라 재작성이다.** 읽는 사람이 다르다 — 내 맥락·주관·회고를 걷어내고 사실·결정·교훈만 남긴다.
> 절대 안 넘기는 것: `brain/` 노트, 개인 회고, 면담·1:1·타인 개인사, 인사·급여·계약액, 고객 식별 정보, raw 원문 통째.

## 1. 접근 경로 확인 (먼저)

승격물의 **종류에 따라 경로가 다르다**(§17.3). 먼저 종류를 정한다.

| 종류 | 경로 | 비고 |
|---|---|---|
| 일일 업무·배운점(EOD) | `tools/company-wiki.py daily-put` → 전사 위키 `raw/reports/daily/<나>/` | 같은 날 다시 올리면 갱신된다 |
| 공유 할 일(늦어지면 남이 불편해지는 일) | `tools/company-wiki.py task-new` → 코드 PR 로 끝나면 그 코드 저장소, 아니면 `bodit-inc/bodit-ops-tasks` 의 issue. 조회는 `task-list` | 미리보기 → 사람 승인 → `--yes`. 남에게 배정할 수 있다 |
| 지식(decision·concept·entity·domain) | `tools/company-wiki.py wiki-pr` → 전사 위키 **PR + 리뷰어 지정**(전사 `docs/guide/contributing.md`) | 미리보기 → 사람 승인 → `--yes` |
| 내 회의록·논문 원문 | `tools/company-wiki.py mine-put` → 전사 위키 `raw/meetings/`·`raw/papers/` 에 main 으로 바로 | 미리보기 → 사람 승인 → `--yes` |

- `jarvis` 미인증·툴 안 보임, `gh` 로그인이나 `project` 권한 없음 → 그 경로는 **건너뛰고 한 줄 고지**. 다른 경로로 우회 기록하지 않는다.
- 전사 repo 가 없으면 후보만 정리해 `wiki/tasks/board.md` 에 `- [ ] 전사 승격: <항목>` 으로 남긴 뒤 종료. 지어내지 않는다.

## 2. 후보 추리기

`$ARGUMENTS` 가 대상을 지정하면 그것만. 비었으면 **`log.md` 의 마지막 `promote` 항목 이후** 생긴 것에서 추린다:
- 오늘·최근 일일 리포트의 **한 일 / 발견 / 결정**
- 새로 만들어진 `wiki/decisions/`·`wiki/concepts/`·`wiki/entities/`·`wiki/domains/` 페이지
- 태스크 보드의 `전사 승격` 대기 항목

각 후보에 **경계 판정**(§17.1)을 적용해 걸러낸다: *다른 파트 사람이 알아야 하나?*
- 후보를 **1줄씩** 제시하고 목적지(전사 어느 영역)를 함께 제안 → 사용자가 채택/기각.
- 남발 금지 — 한 번에 5개를 넘기지 않는다. 애매한 건 기각 쪽으로.

## 3. 중복 확인

쓰기 전에 **전사 위키에 이미 있는지 먼저 본다**:
- 지식: `python tools/company-wiki.py get index.md` 로 전사 위키 목록을 읽고, 관련 페이지가 있으면 `get <경로>` 로 연다. 같은 게 있으면 새로 만들지 말고 **보완**한다.
- EOD: 같은 날 파일이 있는지 `daily-get --date <날짜>` 로 확인한다. `daily-put` 은 같은 날이면 갱신한다.
- `log.md` 의 `promote` 이력으로 내가 이미 올린 것과 겹치는지 재확인.
- 할 일은 `task-new` 가 같은 제목의 열린 issue 를 막는다. 제목만 다른 비슷한 일이 있을 수 있으므로 `task-list` 로 먼저 훑는다.

## 4. 합성 재작성 (채택분만)

- 개인 위키 문장을 **복사하지 않는다**. 다음을 걷어낸다: 1인칭 회고, 주관적 판단·감정, 개인 맥락("어제 내가 …"), 개인 태스크 사정.
- 남기는 것: **무엇이 사실인가 / 무엇이 결정됐고 왜인가 / 다른 사람이 재사용할 교훈**.
- **마스킹은 전사 기준(전사 CLAUDE.md §9)을 따른다.** 농가·업체명은 실명으로 두고, 소 귀표·개체번호(첫·끝만 `5***4`), 급여·계약액·인사 정보, Notion URL, Slack 첨부 파일·비공개 채널 링크는 걷어낸다. 공개 채널 **메시지 링크**는 출처로 남긴다. 개인 위키에서 통과한 것도 다시 본다. 판단이 안 서면 묻는다.
- 올리는 도구의 기계 검사(`check`)가 한 번 더 거르지만, **내가 보내는 건 내가 먼저 마스킹한다**.
- 형식은 **전사 wiki 의 schema 를 따른다**(개인 위키 §5 가 아니라). 전사 CLAUDE.md 를 읽어 frontmatter·디렉토리 규칙을 확인한 뒤 쓴다.
- **md 로만**. 첨부·바이너리는 링크나 stub 으로.
- 출처는 전사에서 참조 가능한 형태로만 남긴다 — 개인 위키 로컬 경로(`raw/...`)를 그대로 적지 않는다.

## 5. 반영

- **EOD**: `python tools/company-wiki.py daily-put <공유본.md>`. 올라갈 내용 전체를 보여주고 **승인받은 뒤** 실행한다. 절차는 `/eod` 6-1.
- **할 일**: 먼저 어디에 둘지 가른다(CLAUDE.md §17.3). 개인 할 일은 개인 보드에 두고 올리지 않는다. 코드 PR 로 끝나는 일은 그 코드 저장소(`--repo`), 코드와 상관없는 일은 기본값 `bodit-inc/bodit-ops-tasks` 에 만든다.
  1. 본문 파일을 세 절로 쓴다: 무엇을, 왜 / 끝났다고 보는 기준 / 출처. 출처에는 개인 위키 로컬 경로를 적지 않는다.
  2. `python tools/company-wiki.py task-new --title "<제목>" --body-file <본문.md> --due YYYY-MM-DD --priority <Urgent|High|Medium|Low> --assignee <위키이름 또는 @계정>` 을 **`--yes` 없이** 실행해 미리보기를 받는다. 필요하면 `--repo`·`--part`·`--status`·`--parent`(하위 이슈) 를 더한다.
  3. 미리보기를 사용자에게 보여 주고 승인받는다. issue 는 만드는 순간 담당자에게 알림 메일이 가서 되돌릴 수 없다. 담당은 남으로도 지정할 수 있다.
  4. 승인받은 뒤에만 같은 명령에 `--yes` 를 붙여 실행한다. 민감 정보 검사에 걸리면 멈추고 사용자에게 보여 준다.
  5. 개인 보드에 같은 일이 있으면 그 줄에 `gh:<owner/repo#n>` 을 붙인다. 이후 상태는 GitHub 에서 관리한다.
- **지식**: 전사 위키 **PR + 리뷰어 지정**으로 올린다(전사 `docs/guide/contributing.md`).
  1. 합성 재작성본을 **전사 schema** 로 임시 파일에 쓴다(§4 형식 규칙). PR 설명(무엇을 / 왜 / 리뷰어가 볼 곳)도 파일로 쓴다.
  2. 리뷰어를 고른다: 그 내용의 당사자 → 주제 파트장 → 여러 파트면 파트별 1명. 자기 자신은 리뷰어가 될 수 없다.
  3. `python tools/company-wiki.py wiki-pr --file <본문.md>:wiki/<영역>/<slug>.md --title "<제목>" --slug <slug> --kind <ingest|decision|edit> --op <ingest|decision> --reviewer <위키 이름> --body-file <설명.md>` 를 **`--yes` 없이** 실행해 미리보기를 받는다. 도구가 형식(frontmatter·제목)과 민감 정보를 검사하고, 봇이 만드는 파일은 막는다.
  4. 미리보기(파일·리뷰어·경고)를 보여 주고 승인받은 뒤에만 `--yes` 로 실행한다. 브랜치를 만들고, 파일과 활동 기록을 올리고, PR 을 열고, 리뷰어를 지정한다. 같은 `--slug` 로 다시 실행하면 열린 PR 에 커밋이 더해진다.
  5. 개인 보드에 `전사 승격 대기` 줄이 있으면 PR 주소를 붙여 완료 처리한다.
- **내 회의록·논문 원문**(`raw/meetings/`·`raw/papers/`)은 PR 없이 `mine-put` 으로 main 에 바로 올린다. 같은 파일명이 있으면 도구가 막는다.
- 오늘 올리지 못한 지식은 `wiki/tasks/board.md` 에 `- [ ] 전사 승격 대기: <항목> · src:<경로>` 로 남기고, 급하면 Slack 으로 먼저 알린다.
- 쓰기 전에 무엇을 쓸지 **초안을 보여주고 승인받는다**.
- 실패하거나 권한이 없으면 멈추고 보고 — 부분 반영 상태를 방치하지 않는다.

## 6. 마무리

- `log.md` append: `## [YYYY-MM-DD] promote | <N>건 → 전사 wiki` + 항목별 한 줄(무엇을 어디로). **중복 방지의 근거가 되므로 빠뜨리지 않는다.**
- 태스크 보드의 승격 대기 항목 완료 처리.
- 한 줄 보고: 채택 N / 기각 M / EOD J / 할 일 T / PR K.

## 톤·안전
- 사용자와의 대화는 **존댓말**, 위키 본문은 **평어체**.
- **승인 게이트**: 전사 쓰기는 되돌리기 어렵다 — 초안 승인 없이 쓰지 않는다.
- 전사 wiki 의 **남의 페이지를 임의로 고치지 않는다**. 내 파트·내가 만든 문서 위주로, 남의 것은 추가·보완만.
- 애매하면 올리지 않는다. 안 올린 건 다음에 올릴 수 있지만, 잘못 올린 건 이미 퍼진다.
