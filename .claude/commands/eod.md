`/eod` (End Of Day) — 하루를 닫으며 ① 회고 대화로 **오늘 일일 리포트를 완성**하고 ② **배운점·개선점을 지식화**하고(brain/decision/concept) ③ 공유 가치가 있는 것을 **전사 wiki 로 승격**한다. `/morning` 의 짝.

> 위키 schema 는 `CLAUDE.md`(§7.3 일일, §4.3 raw, §15.1 역할별 태스크, §17 전사 연계), 지식 레이어는 `brain/README.md`.
> **먼저 `me.md` 의 `역할 유형`(`lead` / `member`)을 읽는다**(§15.1). 값이 없으면 `member` — 6-2 단계의 범위가 갈린다.
> 핵심: 오늘 실제 경험 → 회고 → **brain note(2nd brain)** 로 적재, 굳은 건 wiki(3rd brain)로 승격. "다 올리지 않는다 — 신호 있는 것만"(§7.1·§11).

## 진행 순서

### 1. 오늘 상태 수집
- 오늘 일일 리포트(`raw/reports/daily/<오늘>.md`)를 읽는다. 없으면 `/morning` 1단계와 동일하게 자리를 만들고 "아침 자리 없어 생성함" 한 줄 고지.
- 아침 `## 오늘 할 일` 체크리스트와 `/log` 로 쌓인 줄을 대조해 **완료/이월**을 파악한다.

### 2. 회고 대화 (짧게)
답이 얇은 칸만 되묻고, 장황하게 끌지 않는다:
- **오늘 한 일**: `/log` 로 쌓인 게 있으면 **묻지 말고 먼저 보여준다** — 요약해 제시하고 **빠진 것·틀린 것만** 확인한다. 이미 기록된 걸 다시 부르게 하면 자동 캡처의 의미가 없다. 확인할 것은 **세션에 안 남는 일**(회의·통화·현장·문서 검토)과 이월. `/log` 를 안 썼으면 처음부터 받는다.
- **배운점**: 실제 경험에서 새로 안 것·통찰. (지식화 1순위 재료)
- **개선점·막힘**: 더 잘할 수 있던 것, blocker, 반복되는 문제.
- **오늘의 회고**: 사실 재나열이 아니라 **느낌·판단** 한두 줄. 비워두지 않는다.
- **내일**: 우선 처리할 것 (내일 `/morning` 의 씨앗).

### 3. 초안 제시 · 검토 · 승인 (작성 전 게이트)
- 회고가 끝나면 **바로 쓰지 않는다**. 기록될 초안을 텍스트로 먼저 보여준다:
  - **일일 리포트 초안**(원본·SoT): §7.3 구조(한 일/발견/배운점·느낀점/결정/막힘/내일).
  - **전사 공유본**(전사 연결 시): 위 초안에서 민감분을 걷어낸 판 — **무엇을 뺐는지 함께 보여준다**.
  - **그 밖의 전사 승격 후보**(있으면): 무엇을 어떤 형태로 올릴지 1줄씩.
  - **개인 위키 저장**: 마무리에서 오늘 바뀐 개인 위키 파일을 내 GitHub 저장소에 커밋·push 한다는 것. 여기서 함께 승인받는다.
- 수정 요청은 반영해 다시 보여준다. **승인한 내용만** 다음 단계에서 기록한다.
- 받은 답만 옮긴다 — 빈 칸을 추측으로 채우지 않는다.

### 4. 일일 리포트 완성 — 승인분만
- ⚠️ **새로 쓰는 게 아니라 마감한다.** `/log` 로 이미 쌓인 파일이면 **보강·정리**할 뿐 통째로 덮어쓰지 않는다 — 세션 캡처분이 날아간다.
- 승인된 초안을 오늘 `raw/reports/daily/YYYY-MM-DD.md` 에 반영. `last_updated` 갱신.
- 본문 §7.3 구조: **한 일 / 발견 / 배운점·느낌 / 결정 / 막힘 / 내일**. `/log` 줄들을 정리·합성한다(나열 복사 아님).
- **`## 배운점·느낌` 이 `/eod` 의 고유 몫**이다. 나머지 칸은 `/log` 가 채울 수 있지만 이 칸만은 못 채운다 — 사람 머릿속에만 있다.
- **PII 마스킹**(§9): raw 도 git 에 올라가므로(§4.3) 여기서 이미 마스킹한다. 고객·개인 식별 정보, 계정·토큰, 급여·계약액 제거.
- 여기가 **원본(SoT)** 이므로 솔직하게 적는다. 다만 면담·1:1·타인 개인사처럼 리포트에 어울리지 않는 것은 5단계 brain note 로 보낸다.
- 작성 당일은 mutable, 다음 날부터 immutable(§4.3).

### 5. 지식화 제안 (선별적 — 신호 있는 것만)
회고의 배운점·개선점·결정에서 **재사용 가치** 있는 것만 골라 제안한다(자동 남발 금지):
- 생각·교훈·가설·관찰 → **brain note**(`brain/<slug>.md`, 템플릿 `brain/TEMPLATE.md`).
- 확정된 기술/업무 결정 → **decision**(ADR `wiki/decisions/YYYY-MM-<slug>.md`, §7.6).
- 새 개념·기법, 기존 entity/concept 갱신 → `wiki/concepts/`·`wiki/entities/` (§7.1).
- 각 후보를 한 줄로 제안 → 승인 시에만 작성. **고립 금지**(§6).
- 판단 기준: 6개월 후 참조 가치 / 방법론 변경 근거 / 반복 디버깅 케이스. 단순 일과는 일일 리포트에만.

### 6. 전사 wiki 승격 (§17)

**6-1. 일일 공유본 → 전사 위키 내 폴더 (필수)**

> 저장처는 **전사 위키 `raw/reports/daily/<나>/`** 이고, 도구는 `tools/company-wiki.py` 다.

> **기본값은 "올린다".** EOD 를 쓰면 전사에도 올라간다 — 선택 사항이 아니다(§17.3). 안 올리는 건 예외이며, 그때는 **왜 안 올리는지 한 줄로 남긴다**. 조용히 건너뛰지 않는다.
> 단, **필수인 것은 "올리는 행위"이지 "전부 올리는 것"이 아니다** — 아래 걷어낼 것은 그대로 걷어낸다.

- 4단계에서 기록한 **개인 원본에서 민감분을 걷어낸 판**을 올린다. 새로 쓰는 게 아니라 **같은 리포트의 공유 버전**이다.
  - **걷어낼 것**: 면담·1:1·타인에 대한 판단, 개인 사정, 급여·처우·계약액, 아직 공유 못 할 초기 판단, 개인 태스크 사정.
  - **남길 것**: 한 일 / 발견 / 배운점·느낀점 / 결정 / 막힘 / 내일 — 배운점이 팀 rollup 의 재료다.
- **전사 형식으로 만든다**(전사 위키 `raw/reports/daily/README.md`): frontmatter `type: report` · `report_kind: daily` · `period: <오늘>` · `author: <전사 위키 내 이름>` · `part:` · `tags` · `last_updated`, 본문 제목 `# YYYY-MM-DD (이름)`. 내 이름·파트는 `python tools/company-wiki.py whoami` 로 확인한다.
- **마스킹은 전사 기준**: 농가·업체명은 실명 유지, 소 귀표·개체번호는 마스킹, 급여·계약액·인사 정보는 넣지 않는다.
- **기계 검사 먼저**: 공유본을 임시 파일로 저장하고 `python tools/company-wiki.py check <공유본.md>` 를 돌린다. 전화번호·이력번호·금액·급여 같은 단어·토큰·노션 링크·슬랙 첨부 파일 링크를 **기계적으로** 찾는다(슬랙 메시지 링크는 출처라서 통과한다)(`tools/sensitive-check.txt`). AI 가 가린 뒤에도 남은 것을 한 번 더 잡는 장치다.
  - 걸린 것이 있으면 **가리거나 지운 판으로 고친 뒤 다시 검사**한다. 그래도 남는 것(예: 공개된 회사 대표번호)은 승인 화면에서 따로 짚는다.
- **승인 게이트**: 무엇을 걷어냈는지 한 줄 + **기계 검사 결과** + **올라갈 내용 전체**를 보여주고 승인받는다. 승인 전에는 올리지 않는다. 조용히 빼거나 조용히 넣지 않는다.
  - 기계 검사에 걸린 채로 사용자가 **그 항목을 명시적으로 괜찮다고 했을 때만** `--confirm-sensitive` 를 붙인다. 전체 승인만으로 붙이지 않는다.
- **올리기**: 공유본을 임시 파일로 저장한 뒤
  ```
  python tools/company-wiki.py daily-put <공유본.md> --summary "<한 줄 요약>"
  ```
  - 전사 위키에 **main 으로 바로** 올라가고 활동 기록(`log/`)도 함께 남는다. PR 이 필요 없다 — 내 폴더의 내 파일이라 남과 겹치지 않는다(전사 CLAUDE.md §8).
  - **저장소를 내려받지 않는다.** 거절되면 도구가 최신 상태를 다시 읽고 재시도한다.
  - 같은 날 다시 실행하면 **갱신**된다(중복 파일이 생기지 않는다). 지난 날짜는 도구가 막는다.
  - 올라갈 위치만 먼저 보려면 `--dry-run`.
- **실패하면**: 도구가 낸 안내 문장을 그대로 보여준다(`gh` 미로그인 · 전사 `people/` 에 내 github 계정 없음 등). 개인 원본은 그대로 두고 보드에 `- [ ] EOD 전사 업로드: YYYY-MM-DD` 로 남긴다.
- **"공유할 게 없다"는 판단은 보수적으로.** 걷어내고 나니 남는 게 없는 날은 드물다 — 한 일이 있으면 올린다. 진짜로 전부 민감한 날만 예외이고, 그때도 건너뛴 사실을 보고한다. 빈 리포트만 금지다.

**6-2. 태스크 정리 → 개인 보드 마감 + GitHub 반영 (필수)**

*먼저 개인 보드부터 닫는다.* 오늘 `wiki/tasks/board.md` 에서 **완료 처리**(`- [x]` + 완료일 → ✅), **신규 유입**(오늘 나온 액션), **우선순위·`due:` 변경**을 반영한다. 단 `gh:` 가 붙은 줄은 상태의 원본이 GitHub 이므로 보드에서 체크하지 않는다.

*그다음 오늘 나온 할 일마다 어디에 둘지 판정한다.* 사람에게 판정을 맡기지 않고 **여기서 표를 적용해 초안을 만든다**(전사 task-policy §5-3).

> **이 일이 늦어지면 나 말고 누가 불편해지는가?**

| 하나라도 해당하면 → GitHub | 모두 아니면 → 개인 보드 |
|---|---|
| 담당이 나 아닌 다른 사람이다 · 마감을 남과 약속했다 · 결과를 다른 파트나 외부가 받는다 · 누군가 이걸 기다린다 · 코드 PR 로 끝난다 | 나만 불편하다 (개인 공부·정리·습관·개인 프로젝트) |

- **GitHub 으로 갈 것**은 저장소를 고른다. 코드 PR 로 끝나면 그 코드 저장소(`--repo bodit-inc/<저장소>`), 아니면 기본값 `bodit-ops-tasks`.
- **초안 만들기**: 할 일마다 본문 파일(무엇을, 왜 / 끝났다고 보는 기준 / 출처)을 임시로 쓰고 미리보기를 돌린다.
  ```
  python tools/company-wiki.py task-new --title "<끝이 보이는 한 줄>" --body-file <본문.md> \
    --due <YYYY-MM-DD> --priority <Urgent|High|Medium|Low> --assignee <위키 이름> --status <Inbox|Backlog|This week>
  ```
  - `--yes` 가 없으면 **만들지 않고 미리보기만 낸다.** 도구가 민감 정보 검사와 같은 제목 중복 확인을 함께 한다.
  - 기존 이슈의 하위 일이면 `--parent <번호>` 를 붙인다.
- **승인 게이트**: 올릴 것 전체를 한 번에 보여 준다. 할 일마다 제목·저장소·담당·마감·우선순위, 그리고 도구가 낸 `warnings`(특히 **"담당자에게 알림 메일이 간다"**)를 보여 준다. 사용자가 고르거나 고친 것만 `--yes` 를 붙여 만든다. **전체 승인이 없으면 하나도 만들지 않는다.** 이슈는 만드는 순간 알림이 나가서 되돌릴 수 없다.
- **이미 GitHub 에 있는 내 일**은 승인 없이 상태만 맞춘다: `task-list --mine` 으로 읽고, 오늘 끝낸 것은 `task-close <번호>` 미리보기를 승인 화면에 함께 넣는다. 진행 상태·마감 변경은 `task-update <번호> --status "In progress"` 처럼 바로 한다(내 담당일 때만).
- **개인 보드와 겹치지 않게**: GitHub 으로 올린 줄은 개인 보드의 그 줄에 `gh:<owner/repo#n>` 을 붙인다. 상태는 GitHub 에서만 바꾼다(§15.1).
- **역할별 마무리** — `me.md` 의 `역할 유형`:
  - **`member`**: 여기까지. 내 GitHub 할 일과 개인 보드가 서로 어긋나지 않는지만 확인한다.
  - **`lead`**: 추가로 `task-list --part <내 파트>` 로 **팀 할 일의 진행과 정체**를 훑는다. ① 내가 답을 안 줘서 멈춘 건(Blocked) ② 마감이 지났거나 며칠째 상태가 그대로인 건 ③ 담당이 비어 있는 건. 셋을 내일 할 일·보드 🔥 로 넘긴다.
- **막히면**: `project` 권한이 없거나 로그인이 풀려 도구가 실패하면, 도구가 낸 안내를 그대로 보여 주고 개인 보드에 `- [ ] GitHub 올리기 대기: <할 일> · src:<경로>` 로 남긴다. 실패를 조용히 삼키지 않는다.

**6-3. 그 밖의 지식 승격**
- 오늘 산출물 중 **다른 파트가 알아야 할 것**(공용 결정·개념·entity)은 전사 위키에 **PR + 리뷰어 지정**으로 올린다(§17.3, 실행은 `/promote`). 오늘 올리지 못하면 흘려보내지 말고 보드에 `- [ ] 전사 승격 대기: <항목> · src:<경로>` 로 남긴다. 급한 건 Slack 으로 먼저 알린다.
- **절대 안 넘긴다**: `brain/` 노트, 개인 회고, 면담·개인사, 민감 수치.

**전사 미연결 시**: 4단계 개인 기록은 그대로 두고 전사 단계만 건너뛴 뒤 한 줄 고지한다. 다른 경로로 우회 기록하지 않는다. 미업로드분은 보드에 `- [ ] EOD 전사 업로드: YYYY-MM-DD` 로 남긴다.

### 7. 마무리
- `index.md` 신규 페이지 추가, `log.md` append(§8.2): `## [YYYY-MM-DD] daily | ...` + ingest/decision/brain/promote 줄.
- `wiki/tasks/board.md` 갱신: 완료 처리, 내일 할 일·새 액션 반영.
- **개인 위키 저장 (필수)**: 3단계에서 승인받았으면 오늘 바뀐 개인 위키 파일을 커밋하고 내 GitHub 저장소에 push 한다. 전사에 올린 것과 별개로, 원본인 개인 위키도 저장소에 남아야 다른 컴퓨터에서 이어 쓰고 잃어버리지 않는다.
  - 커밋 메시지는 `eod: YYYY-MM-DD` 처럼 짧게 쓴다. 오늘 작업과 무관한 변경이 섞여 있으면 먼저 보여 주고 뺄지 묻는다.
  - push 가 거절되면(다른 컴퓨터에서 먼저 올린 경우) `git pull --rebase` 후 다시 push 한다. 충돌이 나면 멈추고 보여 준다.
  - git 없이 쓰는 위키(ZIP)면 이 단계를 건너뛰고 한 줄 고지한다.
- 한 줄 보고: `완료 N / 이월 M / 지식화 K / 전사 EOD 업로드 / GitHub 할 일 만듦 G·닫음 C / 개인 위키 push`.
- `lead` 면 여기에 **내가 막고 있는 건 J개**를 덧붙인다 — 이게 내일 아침 `/morning` 의 🔴 이 된다.
- **전사 반영이 하나라도 빠졌으면 마무리에서 반드시 말한다.** 빠진 건 다음 날 밀리므로 조용히 넘어가면 안 된다.

## 톤·안전
- 사용자와의 대화는 **존댓말**, 위키 본문·brain note 는 **평어체**(§3).
- **승인 게이트**: 3단계에서 초안을 보고 승인한 뒤에만 기록한다.
- 민감한 회고는 위키 raw 가 아니라 **brain note** 로만. 전사로는 절대 안 간다.
- **원본은 여기, 공유본은 전사.** 개인 위키가 SoT 이고, 전사에는 걷어낸 판만 간다.
- 지식화는 **선별** — 매일 다 올리지 않는다. 애매하면 brain seed 로 가볍게.
