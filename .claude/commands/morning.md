`/morning` — 아침 업무 시작 루틴. **위키 안에서** 오늘 일일 리포트 자리를 만들고, 어제 흐름과 **전사 wiki** 를 훑어 **오늘 할 일을 확정**한다. `/eod` 의 짝. 외부 도구 종속성 없음(전사 참조는 §17 경로가 있을 때만).

> 위키 schema 는 `CLAUDE.md`(§7.3 일일 리포트, §15 태스크 보드, §17 전사 연계). 전사 접근이 없으면 4단계를 건너뛴다.
> 핵심 가치: **놓치는 것 없이 하루를 시작한다.** 어제 이월 + 보드 우선순위 + 전사에서 나에게 온 것 = 오늘 할 일.
> **먼저 `me.md` 의 `역할 유형`(`lead` / `member`)을 읽는다**(§15.1). 값이 없으면 `member` 로 본다.
> 어제 팀 흐름(4-B)은 **역할과 무관하게 모두 본다.** 역할이 가르는 것은 거기서 **무엇을 더 챙기느냐**다.

## 진행 순서

### 1. 오늘 자리 만들기
- `raw/reports/daily/YYYY-MM-DD.md`(오늘) 존재 확인. **없을 때만** 생성한다.
- frontmatter: `type: report`, `report_kind: daily`, `period: <오늘>`, `status: active`, `tags`, `last_updated`.
- 본문은 §7.3 골격만 비워 둔다: `## 오늘 할 일` / `## 한 일` / `## 발견` / `## 배운점·느낌` / `## 결정` / `## 막힘` / `## 내일`. 내용은 `/log`·`/eod` 가 채운다.
- **`## 오늘 할 일` 을 반드시 만든다** — `/log` 가 완료 항목을 `- [x]` 로 체크하는 대상이다. 없으면 `/log` 의 완료 체크 경로가 죽는다.
- **`## 배운점·느낌` 은 `/eod` 전용 칸**이다. `/log` 는 이 칸을 못 채운다 — 사람 머릿속에만 있다.
- 이미 있으면 그대로 쓰고 아무것도 덮어쓰지 않는다.

### 2. 어제 파악
- 어제 일일 리포트(`raw/reports/daily/`의 직전 영업일 파일)를 읽는다. 없으면 그 사실만 한 줄.
- `/log` 를 무인 실행 중이면(§7.11) 이 파일이 전 레포 세션에서 이미 채워져 있다 — 기억보다 여기가 정확하다.
- 뽑을 것: **미완료 `- [ ]` 항목** / **"내일" 섹션** / 이어지는 작업 / 해소 안 된 **막힘**.

### 3. 태스크 보드 훑기
- `wiki/tasks/board.md` 에서 **🔥 우선 / 📋 진행 중 / 👀 확인 필요** 를 읽는다.
- **기한 임박·초과**(`due:`) 항목을 따로 표시한다 — 일정 관리 보조가 이 커맨드의 핵심 값이다.
- ⏳ **대기(blocked)** 도 훑는다 — 막아 놓은 조건이 풀렸는데 그대로 잠들어 있는 항목이 여기 쌓인다.

### 4. 전사 확인 (§17, 연결됐을 때만) — **역할에 따라 범위가 갈린다**

**묻는 방식**: 파일 탐색이 아니라 질의다 — "어제 우리 파트 EOD 요약", "나에게 배정된 태스크" 처럼 묻는다.
미연결이면 "전사 미연결 — 건너뜀" 한 줄만 남기고 진행한다.

**4-A. 공통 — 나에게 온 것 (`member`·`lead` 모두)**
- **GitHub 할 일**: 나에게 배정된 끝나지 않은 일을 읽는다.
  ```
  python tools/company-wiki.py task-list --mine
  ```
  마감이 지났으면 `⚠지남` 이 붙는다. 마감이 가까운 순으로 나오므로 위에서부터 오늘 할 일 후보다. `project` 권한이 없어 실패하면 한 줄 고지하고 건너뛴다.
- **담당이 비어 있는 내 파트 일**도 한 번 본다: `task-list --part <내 파트> --status Inbox`. 내가 가져갈 것이 있으면 5단계 초안에 넣는다. 담당 지정은 `/eod` 의 승인 화면에서 한다.
- ⚠️ **GitHub 에만 있고 오늘 할 일에 없으면 오늘 안 보게 된다.** 오늘 손댈 것은 `## 오늘 할 일` 에 `gh:<owner/repo#n>` 을 붙여 넣는다. 개인 보드로 옮겨 적어 상태를 두 곳에서 관리하지는 않는다(§15.1).
- **어제 전사 흐름**: 내가 알아야 할 결정·요청·멘션, 특히 **나에게 답을 기다리는 것**.
- 어제 내가 올린 EOD 도 확인한다 — 거기 적은 '내일' 이 오늘 할 일의 씨앗이다.

**4-B. 어제 팀 흐름 — `member`·`lead` **모두** 본다**

동료들이 어제 무슨 일을 했는지는 **직급과 무관하게 알아야 하는 것**이다. 내 일과 겹치거나 이어지는 지점이 거기서 나오고, 몰라서 같은 일을 두 번 하거나 이미 답이 나온 것을 다시 묻는 일이 여기서 막힌다.

- **팀원 EOD**: 전사 위키의 어제 일일 리포트를 읽는다.
  ```
  python tools/company-wiki.py daily-get --date <어제>
  ```
  사람별 리포트와 함께 **쓴 사람·안 쓴 사람**이 끝에 나온다. 저장소를 내려받지 않는다.
- 범위는 전사 위키 `raw/reports/daily/` 의 **공유본**이다. 각자 민감분을 걷어내고 올린 것이라, 남의 사적인 기록을 들추는 것이 아니다.
- **기록처가 사람마다 다르다.** 한 소스만 보고 "이 사람 리포트 공백" 으로 단정하지 않는다. 전사 EOD 에만 쓰는 사람과 팀 공유 문서에만 쓰는 사람이 갈린다. 여러 소스를 쓴다면 합쳐서 보고, **어느 소스를 못 봤는지 밝힌다.**
- 인용할 때는 **작성자와 날짜를 반드시 밝힌다**.
- **대리 저장은 불가하다.** 팀원 EOD 를 대신 써 주지 않는다. 읽기만 한다.

**뽑을 것 — 나열이 아니라 판단이다.** 사람마다 한 일을 그대로 옮겨 적는 요약집을 만들지 않는다.

*모두 (`member`·`lead` 공통)*
- ① **사람별 한 일 한두 줄** — 누가 무엇을 진척시켰나.
- ② **내 일과 닿는 지점** — 내가 기다리던 것이 끝났나, 내 작업의 전제가 바뀌었나, 같은 것을 둘이 하고 있지 않나.
- ③ **내가 알아야 할 결정·요청** — 어제 굳은 결정 중 내 작업 방식을 바꾸는 것.
- ④ **내가 답해야 상대가 움직이는 것** — 나를 기다리며 멈춰 있는 건. 있으면 오늘 할 일의 🔴 로 올린다.

*`lead` 라면 여기에 더한다*
- ⑤ **막힌 사람** — 스스로 못 푸는 것을 들고 있는 사람. 내 결정·방향이 필요한 건은 **내 보드의 🔥 로 옮긴다**(§15.1 유기 지점 3).
- ⑥ **기록이 며칠째 빈 사람** — **마지막 작성일과 함께** 적는다. 챙김 신호이지 추궁이 아니다.
- ⑦ **팀 전체의 방향과 어긋나는 것** — 서로 모순되는 결정, 중복 투자.

- 다른 파트 것은 **내 일과 닿는 지점이 있을 때만** 올린다. 전사 뉴스 요약집이 아니다.
- 팀원이 아직 아무도 EOD 를 안 썼거나 조회가 비면 "어제 팀 기록 없음" 한 줄로 끝낸다. 없는 것을 지어내지 않는다.

### 4-1. 오늘 일정·메일 확인 (Google Calendar · Gmail — 연동됐을 때만)

오늘 할 일 초안(5단계)의 **제약 조건**을 먼저 확보한다. 일정이 하루의 가용 시간을 정하고, 메일에 내 답을 기다리는 게 섞여 있다.

**일정 — `list_events`**
- `startTime`=오늘 00:00, `endTime`=내일 00:00, `timeZone`=본인 시간대, `orderBy: startTime`.
- 응답에 `events` 배열이 없으면 **일정 없음**. "일정 없음" 한 줄로 끝낸다.
- 뽑을 것: 시각·제목·참석자 수. **회의로 막히는 시간 합계**를 계산해 5단계에 반영한다 — 회의가 4시간이면 할 일을 6개 잡으면 안 된다.
- 내일 것도 한 줄 미리 본다(준비가 필요한 회의는 오늘 할 일이 된다).

**메일 — `search_threads`**
- 받은편지함 전체를 훑지 않는다. **광고·뉴스레터가 8할이다.** 아래 3개 질의만 던진다:

| 목적 | query |
|---|---|
| 동료가 보낸 것 | `from:<회사도메인> newer_than:2d -in:sent` |
| 내 PR·CI·이슈 | `is:unread from:notifications@github.com newer_than:2d` |
| 나머지 미읽음 | `is:unread in:inbox newer_than:2d -category:promotions -category:social` |

- **버릴 것**: 제목에 `(광고)`, 뉴스레터(`newsletter@`·`news@`·마케팅 `no-reply`), 채용 플랫폼 추천, 벤더 제품 업데이트.
- **살릴 것**: 사람이 직접 쓴 것 · 내 이름이 `to`(cc 아님)인 것 · **답을 기다리는 것** · GitHub 에서 내 PR·이슈 상태 변화.
- 본문이 필요하면 그때만 `get_thread`. 스니펫으로 판단되면 열지 않는다.
- **읽음 처리·회신·라벨 변경 금지.** 이 단계는 **읽기 전용**이다.

**미연동이면** 한 줄 고지하고 건너뛴다. 두 커넥터 모두 없어도 나머지 단계는 정상 동작한다.

### 4-2. 템플릿 새 판 확인 (하루 한 번, 3초)

```
python tools/template-sync.py --check
```

- "템플릿 새 판 …" 또는 "합치지 못한 파일 …" 이 나오면 **④ 마무리 한 줄에 그대로 옮기고** `/template-update` 를 권한다. 여기서 받지는 않는다.
- "템플릿 최신" 이면 아무것도 말하지 않는다. 도구가 없거나(처음) 확인이 안 되면 한 줄만 알린다.

### 5. 오늘 할 일 초안 → 확정
- `$ARGUMENTS` 가 있으면 그걸 뼈대로. 없으면 2~4-1단계에서 모아 **오늘 할 일 초안**을 만든다:
  - 어제 이월 · 보드 🔥 · 기한 임박 · 전사에서 넘어온 것 · 답장 대기 순으로 배치.
  - 각 줄 한 문장. 5~7개를 넘기면 우선순위를 매겨 **오늘 안 할 것을 명시**한다.
  - **가용 시간과 대조한다**(4-1). 회의로 막힌 시간을 빼고 남는 시간에 안 들어가면 초안에 넣지 말고 오늘 안 할 것으로 명시한다.
- 사용자에게 보여주고 **가감·확정** 받는다. 확정 전에 파일을 쓰지 않는다.
- 확정분을 오늘 일일 리포트 `## 한 일` 위 `## 오늘 할 일` 섹션에 `- [ ]` 로 기록.
- 새로 발견된 액션은 보드에도 반영 제안(§15).

## 출력 포맷 — 네 블록

브리핑은 **항상 이 차례로** 낸다. 순서 자체가 판단이다 — 일정을 먼저 알아야 할 일의 개수가 정해지고, 남이 나를 기다리는 것을 알아야 그중 무엇이 먼저인지 갈린다.

### ① 오늘의 일정
- 회의 표(시각·이름·참석), 반차·재택·출장 같은 근무 조건.
- 표 아래에 **회의로 막히는 시간 합계와 실작업 가능 시간**을 한 줄로 결론낸다: "회의 4시간, 실작업은 오전뿐입니다" 처럼. 여기서 정해진 가용 시간이 ②의 상한이다.
- 일정 커넥터가 없으면 이 블록은 "일정 미연동" 한 줄로 대체한다.

### ② 오늘 할 일 초안
- 시간대로 묶는다(오전 실작업 / 회의 / 남는 시간). 항목마다 **왜 오늘인지**를 한 조각 붙인다(어제 이월·`due:` 임박·오늘 현장 일정 등).
- 🔴 **내가 답해야 풀리는 것**을 별도 소절로 세운다 — 남이 나를 기다리며 멈춰 있는 건. 내 일보다 먼저 처리해야 팀이 안 막힌다. (`lead` 면 4-B 에서, `member` 면 4-A 와 메일에서 나온다.)
- 회의는 **안건까지** 적는다. 그 회의로 `due:` 가 걸린 보드 항목이 있으면 끌어온다.
- 가용 시간을 넘기면 **넣지 말고 "오늘 안 할 것"으로 명시**하거나 범위를 좁히자고 제안한다. 다 담아 놓고 못 하는 것이 제일 나쁘다.

### ③ 어제 흐름 (나 + 팀)
- **내 것**: 어제 내 리포트에서 이어지는 것 + 전사에서 나에게 온 것.
- **팀 것 (역할과 무관하게 낸다)**: **사람별 한두 줄**, **작성자·날짜를 밝힌다.** 🔗 = 내 일과 닿는 것, 🔴 = 내 답을 기다리는 것, ⚠️ = 어긋나 있거나 위험한 것으로 표시한다.
- **`lead` 면 여기에**: 막힌 사람과 **기록이 며칠째 빈 사람**(마지막 작성일과 함께). 챙김 신호로 적는다.
- 맨 끝에 **소스 커버리지 한 줄** — 어느 소스를 못 봤고 누가 빠졌을 수 있는지. 못 본 것을 본 것처럼 넣지 않는다.

### ④ 마무리 한 줄
`오늘 자리 생성됨 / 할 일 N개 / 이월 M / 기한 임박 K / 회의 H시간 / 답장 대기 J / 내가 막고 있는 것 I건`

- 놓치면 안 될 것 1~2개는 **따로 강조**한다.
- 전사·일정·메일 중 건너뛴 소스가 있으면 여기서 한 줄로 밝힌다.
- 템플릿 새 판이 있으면 **한 줄**로 붙인다: `템플릿 새 판 N개(…) — /template-update`.

## 톤·안전
- 사용자와의 대화는 **존댓말**, 위키 본문은 **평어체**(§3).
- 기존 파일을 덮어쓰지 않는다 — 오늘 파일이 이미 있으면 추가만.
- 전사 wiki 는 이 커맨드에서 **읽기만** 한다. 쓰기는 `/promote`·`/eod` 소관.
- 할 일 목록을 AI 가 임의로 확정하지 않는다 — 초안 제시 후 사용자 확정.
