# 개인 LLM Wiki — 템플릿

> AI 와 함께 일하고 성장하기 위한 **개인 지식·맥락 시스템**.
> 배운 걸 의도적으로 쌓고, AI 가 그걸 재료로 일하게 한다.

이 repo 를 가져가 본인 개인 위키로 쓴다. 개인 정보는 들어 있지 않다. `me.md` 만 채우면 동작한다.
**git 을 몰라도 시작할 수 있다** — 폴더로 내려받아 쓰는 경로가 §2 에 있다.

---

## 0. 한 장 요약

- **무엇**: markdown 으로 된 개인 지식 베이스 + Claude Code slash command 자동화.
- **왜**: 우리는 매일 배우는데 그 배움이 휘발한다. 의도적으로 쌓아두면 AI 가 나를 알고, 내 맥락 위에서 일한다. (= **PCM, Personal Context Management**)
- **어떻게**: 3개의 레이어(`raw`·`brain`·`wiki`) + 하루 루프(`/morning` → `/log` → `/eod`).
- **전사 wiki 와의 관계**: 개인은 **여기서만 작업**한다. 회사 공용 지식은 **Jarvis MCP** 로 참조하고(`jarvis_ask`), 일일 리포트는 **원본은 여기 남기고 민감 제외 공유본만** 전사 위키로 올린다(`tools/company-wiki.py`). 공유 할 일은 GitHub issue 로 만든다. 개인 회고와 `brain/` 은 절대 안 넘어간다. (§6)

> 핵심 한 줄: **맥락을 준 만큼 AI 가 증폭된다.** `me.md` 한 장이 모든 AI 도구의 출력 품질을 바꾼다.

## 1. 왜 개인 LLM wiki 인가

### 1-1. 맥락이 없는 AI 는 평균값을 준다

같은 질문을 해도, 나를 모르는 AI 는 **누구에게나 통하는 일반론**을 답한다. 내가 무슨 일을 하는지, 어떤 결정을 이미 내렸는지, 무엇을 어려워하는지 모르기 때문이다. 그래서 매번 배경 설명을 다시 붙이게 되고, 붙이다 지치면 그냥 검색 대용으로 쓰게 된다.

**AI 가 나를 알면 답의 시작점이 달라진다.** 내 역할, 지금 하는 프로젝트, 지난달에 내린 결정, 내가 약한 지점을 알고 있으면 첫 답변부터 내 상황에 붙는다. 이 repo 는 그 '나'를 파일로 만들어 두는 곳이다.

- `me.md` = 내가 누구이고 무엇을 중요하게 여기는가 (Meaning)
- `wiki/`·`brain/`·`raw/` = 내가 무엇을 알고 무엇을 겪었는가 (Assets)
- `CLAUDE.md` = AI 가 나와 어떻게 일하는가 (Actions·Persona)

### 1-2. 증폭기 모드 — 대체가 아니라 증폭

AI 를 쓰는 방식은 크게 둘로 갈린다.

| | **대체 모드** | **증폭기 모드** (이 위키가 지향하는 것) |
|---|---|---|
| 무엇을 맡기나 | 생각까지 맡긴다 | 생각은 내가 하고, **재료 수집·정리·연결·검토**를 맡긴다 |
| 내 맥락 | 안 준다(줄 게 없다) | **누적된 맥락을 재료로 준다** |
| 결과물의 주인 | AI 의 평균적 답 | **내 판단이 담긴 결과물** |
| 시간이 지나면 | 매번 처음부터 | **쌓일수록 빨라진다** |

**AI 는 내 사고를 대신하는 것이 아니라 보완한다.** 내가 놓친 관점을 꺼내 주고, 흩어진 기록을 이어 주고, 잊고 있던 결정을 다시 꺼내 준다. 판단은 여전히 내 몫이다. 그래서 이 템플릿의 커맨드는 대부분 **초안을 만들어 보여주고 사람의 승인을 받는** 구조로 되어 있다. AI 가 임의로 확정하지 않는다.

이 원칙은 `brain/`(2nd brain)에서 특히 강하다. 내 생각을 적는 칸을 **AI 가 대신 채우지 않는다**(CLAUDE.md §16). 질문으로 끄집어낼 뿐이다.

### 1-3. 그래서 무엇이 달라지나

- **놓치지 않는다.** 어제 이월된 일, 남이 나를 기다리는 일, 기한이 지난 일을 아침에 AI 가 먼저 짚어 준다.
- **다시 설명하지 않는다.** "우리가 그때 왜 그렇게 정했더라"를 위키가 답한다.
- **회고가 지식이 된다.** 하루 회고에서 나온 교훈이 그날로 끝나지 않고 `brain/`·`wiki/` 에 남는다.
- **기록이 부담이 아니다.** `/log` 가 세션에서 자동으로 캡처하므로, 저녁에 "오늘 뭐 했지"를 떠올릴 필요가 없다.

> 거창하게 시작하지 않는다. **`me.md` 한 장, 하루 한 줄.** 쌓이는 사람이 AI 시대에 가장 빨리 성장한다.

## 2. 5분 시작 (Quickstart)

> **혼자 처음부터 설정한다면 [START-HERE.md](START-HERE.md) 를 따라간다.** 계정 준비부터 첫 `/eod` 까지 화면 단위로 적은 매뉴얼이다. 아래는 요약이다.

### 2-1. 먼저 가져오기 — 두 갈래 중 하나

**A. git 을 쓴다면 (권장)**

1. 이 repo 에서 초록색 **Use this template** → **Create a new repository** 를 누른다. **Owner 는 본인 계정**, **Private** 을 고른다.
2. 로컬에 clone 한다. 폴더 이름은 자유롭게 정한다(예: `my-llm-wiki`).

> ⚠️ **Fork 버튼으로 만들지 않는다.** 포크는 원래 저장소(회사 조직)의 권한을 물려받아서, 조직의 다른 사람이 내 개인 위키에 접근할 수 있게 된다. 이미 포크로 만들었다면 [MIGRATE-FROM-FORK.md](MIGRATE-FROM-FORK.md) 로 옮긴다.

git 을 쓰면 **이력·백업·기기 이동이 전부 해결되고**, claude.ai 웹에서도 같은 위키를 열 수 있다.

**B. git 을 안 쓴다면 — 폴더로 내려받기**

터미널이나 git 을 안 써도 시작할 수 있다. **위키의 알맹이는 그냥 markdown 파일 묶음**이기 때문이다.

1. GitHub 에서 이 repo 의 초록색 **Code** 버튼 → **Download ZIP**.
2. 압축을 풀어 원하는 위치에 둔다. 폴더 이름은 자유롭게 바꾼다(예: `my-llm-wiki`).
3. 그 폴더에서 Claude Code 를 연다. **이것만으로 커맨드가 전부 동작한다.**

이때 알아둘 것:

| | git 없이 쓸 때 |
|---|---|
| 커맨드·위키·brain | **전부 정상 동작한다** |
| 되돌리기·변경 이력 | 없다. 실수로 지우면 복구가 안 된다 |
| 백업 | 수동이다. 폴더를 OneDrive·Google Drive 안에 두면 자동 백업이 된다 (**권장**) |
| 다른 기기·웹(claude.ai) | 안 된다. 그 PC 안에서만 쓴다 |
| 템플릿 업데이트 | ZIP 을 다시 받아 **바뀐 파일만 골라 덮어쓴다** (§2-3) |

> **나중에 git 을 붙여도 된다.** 그 폴더에서 `git init` → GitHub 에 private repo 를 만들어 연결하면, 그때까지 쌓인 기록이 그대로 첫 커밋이 된다. 먼저 쓰기 시작하는 것이 먼저다.

### 2-2. 공통 — 첫 실행 (A·B 어느 쪽으로 가져왔든 같다)

1. **`me.md` 를 연다.** L1(인생·가치)만 본인 손으로 채운다. AI 가 못 지어내는 부분이다. 나머지는 한 줄씩만 적는다.
   - **`역할 유형`(`lead` / `member`) 한 줄은 꼭 채운다.** 커맨드가 이 값을 보고 보는 범위를 바꾼다(§5).
2. Claude Code 를 그 폴더에서 실행한다. CLAUDE.md 가 자동 로드되고 첫 줄 `@me.md` 로 '나'를 안다.
3. 첫 brain note 를 써 본다: `/brain <요즘 하는 생각 한 줄>`
4. 하루 끝에 `/eod` 로 오늘을 회고하고 지식화한다.

> 처음 합류해 세팅부터 필요하면 [ONBOARDING.md](ONBOARDING.md) 를 따라간다(온보더 체크리스트 포함).
> 전사(Jarvis) 연결은 §6 에서 3분이면 끝나지만, **미뤄도 된다.** 위키 + brain + `/morning`·`/log`·`/eod` 만으로 충분히 시작된다. 환경 설정 상세는 [SETUP.md](SETUP.md).

### 2-3. 템플릿이 업데이트되면 · 이미 쓰던 위키를 회사 GitHub 과 연결하려면

**템플릿을 다시 복사하지 않는다.** 그동안 쌓은 기록이 사라진다. 대신 명령 하나로 받는다.

```
/template-update
```

- 바뀐 것과 **사람이 할 일**을 먼저 보여 주고, 승인받아 받는다. 판별 변경 내용은 [CHANGELOG.md](CHANGELOG.md), 방법과 규칙은 [UPDATE.md](UPDATE.md).
- 내가 안 고친 파일은 새 판으로, **내가 고친 파일(`CLAUDE.md` 포함)은 3방향으로 합친다.** 내가 지운 파일은 다시 받지 않는다.
- **안 건드리는 것**: `me.md`, `brain/`, `raw/`, `wiki/`, `index.md`, `log.md`, `tools/slack-ingest/channels.json`, `.env`
- `/morning` 이 새 판을 보면 한 줄로 알린다. 명령이 아직 없으면 [UPDATE.md](UPDATE.md) 의 "처음 한 번" 을 따라 한다.
- 회사 GitHub·전사 위키와 처음 잇는 것은 [GITHUB-CONNECT.md](GITHUB-CONNECT.md) 다(한 번만).

## 3. 3-Brain — 핵심 구조

| 레이어 | 폴더 | 무엇 | 누가 쓰나 |
|--------|------|------|-----------|
| 1st brain | — | 직관·감성 (나 자신) | 사람 |
| **2nd brain** | `brain/` + `raw/` | 내 생각·가설 + 캡처한 재료 | **사람** |
| 3rd brain | `wiki/` | AI 가 컴파일한 중립 지식 | AI |

- `raw/` = **불변 입력**(원본 캡처). **전부 md** 로 저장하고 git 으로 추적한다(CLAUDE.md §4.3).
- `brain/` = **내 생각**(주관·가설·반론). "그래서 내 생각은?" **전사로 절대 안 넘어간다.**
- `wiki/` = **합성 지식**(중립·재사용). "X 는 무엇인가?"

> 왜 2nd 와 3rd 를 나누나? 생각과 지식을 섞으면 위키가 노이즈로 가득 찬다. **신호 대 잡음비**를 지키는 것이 핵심이다.

흐름: 직관 → `/brain` 으로 끄집어내 `brain/` 적재 → 굳으면 AI 가 `wiki/`(decision·concept)로 **승격** → 공유 가치가 있으면 전사 wiki 로 **승격**. "모든 걸 올리지 않는다. 신호 있는 것만."

## 4. 하루 루프

```
아침  /morning   → 오늘 자리 + 어제 파악 + 전사 확인 + 일정·메일 → 오늘 할 일 확정
중간  /log       → 그때그때 한 일 한 줄 캡처 (세션에서 자동으로 읽는다)
      /brain     → 떠오른 생각을 2nd brain 으로
퇴근  /eod       → 회고 → 일일 리포트 완성 → 지식화 → 전사 반영
```

`/log` 는 **묻지 않고 세션에서 읽어 쓴다.** 모든 레포의 Claude Code 세션을 훑어 한 일을 오늘 리포트에 넣는다. `tools/install-hourly-log.ps1` 로 매 시간 무인 실행도 가능하다(활동이 없으면 LLM 을 호출하지 않는다).

**일일 루틴이 곧 지식화 파이프라인이다.** 따로 시간을 내서 정리하는 것이 아니라, 매일 일하는 흐름에 지식화가 얹힌다.

## 5. 팀과 함께 쓰기 — 무엇을 같이 보고, 역할에 따라 무엇이 갈리나

`me.md` L2 의 **`역할 유형`** 한 줄이 `/morning`·`/eod` 의 동작을 바꾼다(CLAUDE.md §15.1). 값이 없으면 `member` 로 본다.

> **어제 동료들이 무슨 일을 했는지는 역할과 무관하게 모두 본다.** `/morning` 이 전사 위키의 어제 일일 리포트를 읽어 정리해 준다. 예전에 Notion 일일 리포트를 다 같이 보던 것과 같은 자리다. 읽는 것은 각자 민감분을 걷어내고 올린 **공유본**이다.
> 역할이 가르는 것은 *보느냐 마느냐* 가 아니라 거기서 **무엇을 더 챙기느냐** 다.

| | **member** (팀원) | **lead** (파트장·팀장·리드) |
|---|---|---|
| 책임 범위 | **내 태스크**: 개인 보드 + 나에게 배정된 GitHub 이슈 | 위 전부 + **내 파트 이슈의 진행 상황**(Bodit Tasks 보드) |
| 어제 팀 흐름 | **본다.** 사람별 한 일 · 내 일과 닿는 지점 · 내가 답해야 상대가 움직이는 것 | 위에 더해 **막힌 사람 · 기록이 며칠째 빈 사람 · 팀 방향과 어긋나는 것** |
| `/morning` | 내 보드의 🔥·📋·기한 임박 + 나에게 배정된 GitHub 이슈 | 추가로 팀의 막힘을 **내 보드 🔥 로** 끌어온다 |
| `/eod` | 오늘 완료·신규를 보드에 반영하고, 공유 할 일만 GitHub issue 초안으로 만들어 승인받는다 | 추가로 내 파트 이슈의 진행·정체를 정리하고, 내가 막고 있는 건을 내일 먼저 처리하게 넘긴다 |
| 판단의 중심 | *오늘 내가 무엇을 끝냈고, 팀의 어떤 움직임이 내 일에 닿나* | *팀이 무엇에 막혀 있고 내가 무엇을 풀어줘야 하나* |

**개인 태스크와 팀·전사가 붙는 지점은 셋이다.**

1. **개인 보드 → GitHub** (`/eod`): 보드에서 굳은 것 중 **공유 할 일만** GitHub issue 로 올린다(`tools/company-wiki.py task-new`). 미리보기를 보고 승인해야 만들어지고, 남에게 배정할 수도 있다. 올린 줄에는 `gh:<owner/repo#n>` 이 붙고 상태는 GitHub 에서 관리한다. 개인 습관·개인 프로젝트는 보드에만 남는다.
2. **GitHub → 하루 계획** (`/morning`): 나에게 배정된 이슈를 `task-list --mine` 으로 읽어 오늘 할 일에 넣는다. 이렇게 읽지 않으면 GitHub 에만 있는 일을 그날 안 보게 된다.
3. **팀 흐름 → 내 할 일** (`/morning`, 모두): 어제 팀 기록에서 **내가 답해야 상대가 움직이는 것**이 나오면 오늘 할 일의 🔴 로 올린다. `lead` 는 여기서 한 겹 더 봐서, 팀원이 스스로 못 푸는 막힘 중 내 결정이 필요한 건을 **내 보드의 🔥 로** 옮긴다.

> 전사가 연결돼 있지 않아도 전부 동작한다. 전사 단계만 건너뛰고 개인 보드는 그대로 쓴다.

## 6. 전사 wiki 연결 (Jarvis MCP) — 3분

> 이미 개인 위키를 쓰고 있다면 연결 순서는 **[GITHUB-CONNECT.md](GITHUB-CONNECT.md)** 를 따른다(15분).

회사 공용 지식과 일일 리포트는 **전사 LLM wiki** 에 있다. 공유 할 일은 **GitHub issue** 로 두고, 조직 보드 **Bodit Tasks**(https://github.com/orgs/bodit-inc/projects/7)가 모아 보여 준다. 사내 질의는 **MCP 커넥터**로 하고, 사내 표준 커넥터가 **Jarvis** 다.

**전제**: @bodit.co Google 계정 + 대시보드 `users` 에 등록된 활성 사용자.

**Claude Code (CLI)**
```bash
claude mcp add --transport http jarvis https://jarvis-mcp.bodit-lab.co/mcp -s user
```
그다음 `/mcp` 를 입력하면 인증이 뜬다. 브라우저에서 **Google 로그인(@bodit.co)** 하면 끝난다.

**Claude Desktop / Web (claude.ai)**
Settings → Connectors → **Add custom connector** → URL `https://jarvis-mcp.bodit-lab.co/mcp` → 연결 → Google 로그인 → Authorize.

연결되면 툴이 여러 개 보이지만 쓰는 것은 `jarvis_ask` 하나다.

| 툴 | 하는 일 | 성격 |
|---|---|---|
| `jarvis_ask` | 사내 위키·정책·개념·축산 운영 DB 를 자연어로 질의 | 읽기 |
| `jarvis_eod_save` · `jarvis_team_eod` · `jarvis_task_create` | 쓰지 않는다. 일일 리포트는 `tools/company-wiki.py daily-put`·`daily-get`, 할 일은 `task-new`·`task-list` 로 한다(SETUP.md §2-1) | — |

**꼭 알아둘 것**

- **할 일은 GitHub issue 로 다룬다.** 공유 할 일만 `tools/company-wiki.py task-new` 로 만든다. 미리보기를 보고 승인해야 만들어지고, 남에게 배정할 수도 있다. 개인 할 일은 개인 보드에 둔다. GitHub 토큰에 `project` 권한이 필요하다(SETUP.md §2-1).
- **연결을 미뤄도 된다.** 커맨드가 전사 단계를 건너뛰고 한 줄만 고지한다. 개인 위키 기능은 전부 정상이다.
- **지식 페이지(decision·concept·entity)는 전사 위키에 PR 로 올리고 리뷰어를 지정한다**(전사 `docs/guide/contributing.md`). `/promote` 가 `tools/company-wiki.py wiki-pr` 로 브랜치·PR·리뷰어 지정까지 한 번에 하고, 올리기 전에 미리보기를 보여 준다.
- **개인 회고와 `brain/` 은 어느 경로로도 넘어가지 않는다.** 일일 리포트도 원본은 개인 위키에 남고, **민감분을 걷어낸 공유본**만 전사로 간다. 무엇을 걷어냈는지 매번 보여준다.

> 문제 해결 표와 상세 절차는 [SETUP.md](SETUP.md) §2 에 있다.

## 7. 커맨드 (Actions)

| command | 하는 일 | 필요한 설정 |

| `/brain` | brain note(2nd brain) 작성 | 없음 |
| `/brain-check` | brain 거리 감지·제안 (상시) | 없음 |
| `/meeting-ingest` | 회의 스크립트 → **원문 + 정리본**(액션 표 포함) | 없음 (PDF 는 pandoc·Chrome) |
| `/pdf-ingest` | 외부 PDF → md 발췌 → 개인지식화 | 없음 |
| `/monthly` | 월간 합성 + 전사 공유 리스트 | 없음 |
| `/promote` | 개인 산출물 → 전사 wiki 승격, 할 일 → GitHub issue | `gh` 로그인·`project` 권한 (Jarvis 는 있으면 사용) |
| `/slack-ingest` | 슬랙 대화 → 지식화·태스크 (공개 채널은 NAS 공용 보관함, 비공개 채널은 선택 수집) | 사내망·NAS 로그인, 비공개 채널은 Slack 토큰 ([SLACK-GUIDE.md](SLACK-GUIDE.md)) |
| `/repo-ingest` | *(개발자용)* 코드 레포의 새 작업 → 위키 | 형제 코드 레포 |
| `/session-retro` | *(개발자용)* 세션 회고 → 룰·skill 승격 | 없음 |

> **처음엔 `/morning`·`/log`·`/eod`·`/brain` 4개면 충분하다.** 나머지는 필요해질 때 하나씩 켠다.
> *(개발자용)* 은 코드 레포를 다루는 사람만 쓴다. 안 쓰면 그 파일을 지워도 된다.

## 9. 도입 단계 (작게 시작하기)

1. **Day 1**: `me.md` 의 L1 과 `역할 유형` 채우기 + 첫 `/brain`. 그것이 전부다.
2. **Week 1**: 하루 끝 `/eod` 습관. 위키에 concept·decision 이 1~2개 쌓인다.
3. **Week 2+**: `/morning` 으로 하루를 열고, `/pdf-ingest`·`/meeting-ingest` 로 읽은 자료와 회의를 지식화한다. 태스크 보드를 실제로 쓰기 시작한다.
4. **필요해지면**: 전사 연동(§6, `/promote`), 슬랙 정리(`/slack-ingest` — 공개 채널은 NAS 폴더만 열면 되고, 비공개 채널은 토큰을 연결한다).

## 10. 규칙 한눈에 (자세히는 CLAUDE.md)

- 본문은 평어체로 쓰고, **파일명·태그·slug 는 영어 kebab-case** 로 통일한다.
- `raw/` 는 수정하지 않는다(일일 리포트만 작성 당일까지 예외). **전부 md 로** 저장한다.
- 새 페이지는 **고립시키지 않는다**. 들어오는 링크를 1개 이상 확보한다.
- 개인·고객 식별 정보는 **마스킹**한다. raw 도 커밋되므로 raw 에도 적용한다.
- 생각(`brain/`)과 지식(`wiki/`)을 섞지 않는다.
- **전사로 넘기는 것은 업무와 배운점뿐이다.** 개인 회고와 `brain/` 은 여기 남는다.
- AI 는 초안을 제시하고 **사람이 승인한 것만** 기록한다. 임의로 확정하지 않는다.
